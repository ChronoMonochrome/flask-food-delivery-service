# Документация проекта

Репозиторий представляет собой микросервисное приложение, объединяющий бэкенд-сервисы, Telegram-бота, клиентское веб-приложение (фронтенд) для заказа еды (с конструктором WOK и интеграцией с платежной системой и IIKO) и сервис аналитики заказов.

## Структура проекта

```
.
├── back/                            # Бэкенд-приложение и Telegram-бот (Python)
│   ├── app/                         # Основной код Flask-приложения (API, модели, сервисы)
│   │   ├── api.py                   # Описание RESTful API эндпоинтов
│   │   ├── models.py                # SQLAlchemy модели базы данных
│   │   ├── routes.py                # Маршрутизация Flask
│   │   ├── analytics_service.py     # Сервис аналитики
│   │   ├── iiko_service.py          # Сервис интеграции с системой IIKO
│   │   ├── yookassa_service.py      # Сервис интеграции с платежной системой ЮKassa
│   │   └── scheduler.py             # Сервис периодических задач (планировщик)
│   ├── bot/                         # Код Telegram-бота
│   │   └── main.py                  # Точка входа для запуска бота
│   ├── certs/                       # SSL-сертификаты для Nginx (локальные/продуктовые)
│   │   ├── fullchain.pem
│   │   └── privkey.pem
│   ├── migrations/                  # История миграций базы данных (Alembic)
│   │   └── versions/                # Скрипты изменений схемы БД

│   ├── scripts/                     # Вспомогательные bash и python скрипты (БД, синхронизация)
│   ├── alembic.ini                  # Конфигурация Alembic
│   └── requirements.txt             # Зависимости Python-окружения
│
├── front/                           # Фронтенд-приложение (React + Vite + TypeScript)

│   ├── tailwind.config.js           # Конфигурация Tailwind CSS
│   ├── vite.config.ts               # Конфигурация сборщика Vite
│   └── package.json                 # Зависимости и скрипты Node.js

├── docker-compose.yml               # Оркестрация Docker-контейнеров всего стека
├── Dockerfile.web                   # Контейнер для Flask API
```

## Настройка окружения

### 1. SSL-сертификаты

Для корректной работы Nginx и обработки HTTPS-запросов (необходимо для WebApp Telegram и веб-хуков платежных систем) поместите ваши SSL-сертификаты в директорию `back/certs/`:

* `back/certs/fullchain.pem`
* `back/certs/privkey.pem`

### 2. Переменные окружения

Создайте файл `.env` в корневом каталоге проекта на основе предоставленного примера:

```bash
cp .env.example .env

```

Заполните ключевые переменные конфигурации:

* **База данных (сервис `db`):** `MYSQL_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`.
* **Бэкенд (`web`):** `DATABASE_URL`, `SECRET_KEY`.
* **Telegram:** `BOT_TOKEN` (от BotFather), `WEB_APP_URL` (внешний адрес вашего развернутого приложения).
* **Интеграции:** Настройки для `IIKO_API_URL`, `IIKO_API_TOKEN` и параметры платежного шлюза ЮKassa.

*Для фронтенда при необходимости локальной разработки используются файлы конфигурации внутри директории `front/` (`.env.development`, `.env.production` и т.д.).*

## Запуск приложения

Для автоматизации сборки и развертывания всех сервисов в Docker-контейнерах используется скрипт `start_app.sh` или стандартный вызов Docker Compose.

```bash
# Вариант 1: запуск через готовый скрипт
chmod +x start_app.sh
./start_app.sh

# Вариант 2: стандартная сборка и запуск контейнеров в фоне
docker compose up --build -d

```

### Архитектура контейнеров:

1. `web` — обслуживает Flask API и админ-панель.
2. `bot` — запускает обработчик команд Telegram-бота.
3. `scheduler` — отвечает за фоновую синхронизацию данных (меню, заказы) по расписанию.
4. `analytics_service` — микросервис для агрегации и обработки метрик и данных по заказам.
5. `mock_iiko_api` — изолированный сервис-заглушка для отладки интеграции с IIKO без обращения к боевому серверу.
6. `nginx` — проксирует запросы к фронтенду и API, отвечает за SSL.

### Первичная инициализация базы данных

После первого успешного запуска контейнеров необходимо применить миграции Alembic для формирования таблиц в базе данных:

```bash
docker compose run --rm web flask db upgrade

```

## Доступ к приложению

* **Клиентский Web-интерфейс:** Доступен по доменному имени или IP-адресу, настроенному в конфигурации Nginx (`nginx.conf`).
* **Telegram-бот:** Запустите бота в клиенте Telegram, отправив команду `/start`. Нажатие на встроенную кнопку WebApp откроет веб-интерфейс заказа.
* **Панель аналитики:** Доступна для мониторинга бизнес-показателей по ссылке [https://mybuildserver-analytics.ignorelist.com/dashboard](https://mybuildserver-analytics.ignorelist.com/dashboard).

## API-эндпоинты (Backend)

Веб-приложение предоставляет RESTful API для интеграции с фронтендом. Интерактивная документация Swagger доступна по адресу `/api/doc`.

### Основные эндпоинты:

* **`GET /api/categories`** — Получить список всех категорий меню (Пицца, Бургеры, WOK и т.д.).
* **`GET /api/products`** — Получить список доступных блюд (с поддержкой фильтрации по query-параметру `categoryId`).
* **`GET /api/products/<product_id>`** — Детальная информация о конкретном блюде, его составе и модификаторах.
* **`GET /api/addons`** — Список доступных топпингов и добавок.
* **`GET /api/recommendations`** — Дополнительные товары, рекомендуемые к покупке при оформлении заказа.
* **`GET /api/orders`** — Получить историю заказов текущего пользователя.
* **`POST /api/orders`** — Создать новый заказ. Передается состав корзины (items, addons) и структура `deliveryInfo` (адрес, телефон, тип оплаты). Сведения о созданном заказе автоматически транслируются в микросервис аналитики.

## Работа с логами и обслуживание

Для мониторинга состояния отдельных систем используйте стандартные команды логирования контейнеров:

```bash
# Просмотр логов бэкенда (Flask)
docker compose logs web

# Просмотр логов работы Telegram-бота
docker compose logs bot

# Просмотр логов микросервиса аналитики
docker compose logs analytics_service

# Мониторинг логов в реальном времени для всех сервисов
docker compose logs -f

```

### Скрипты администрирования

В каталоге `back/scripts/` находятся дополнительные утилиты для обслуживания:

* `sync_db.sh` / `run_sync_once.py` — принудительный ручной запуск синхронизации меню с IIKO.
* `print_db_data.py` — вывод текущей информации из таблиц БД в консоль для проверки целостности.
* `drop_db_tables.py` / `drop_db.sh` — полная очистка таблиц базы данных (используйте с осторожностью!).

## Остановка проекта

Чтобы остановить контейнеры и освободить порты:

```bash
docker compose down

```

Для полной очистки окружения, включая удаление локальных Docker-томов (данные базы данных при этом будут стерты):

```bash
docker compose down -v

```
